3 ПРОГРАММНАЯ РЕАЛИЗАЦИЯ ПРОГРАММНОГО МОДУЛЯ

3.1 Обоснование средств реализации

3.1.1 Для реализации программного модуля используется система управления базами данных PostgreSQL, которая предназначена для хранения и управления структурированной информацией. Выбор PostgreSQL обусловлен её надёжностью, расширяемостью и активным использованием в современных корпоративных и научных информационных системах.

PostgreSQL – это объектно-реляционная СУБД с открытым исходным кодом, обеспечивающая высокий уровень соответствия стандарту SQL, поддержку ACID-транзакций, богатый функционал и возможность создания пользовательских функций. Она активно применяется в проектах, где важны надёжность, масштабируемость и строгая целостность данных.

Среди основных преимуществ PostgreSQL можно выделить:
- поддержка расширенного SQL. Оконные функции, CTE (common table expressions), частичные индексы, тип JSON и другие возможности для сложных запросов;
- высокая надёжность, благодаря использованию механизма журналирования (WAL), транзакции не теряются даже при сбое системы;
- расширяемость, возможность подключения дополнительных модулей и написания пользовательских функций на SQL, Python, C и других языках;
- поддержка полнотекстового поиска, географических данных (через PostGIS) и нетривиальных типов данных (массивы, hstore, jsonb);
- безопасность, гибкая система управления доступом и поддержка аутентификации через SSL, GSSAPI, SSPI и другие протоколы.

Недостатки PostgreSQL:
- сложность администрирования по сравнению с более простыми СУБД (например, SQLite или MySQL);
- требовательность к ресурсам на масштабируемых или сильно нагруженных системах;
- некоторые инструменты требуют настройки вручную, особенно в случае кластеризации или репликации.

Выбор PostgreSQL обусловлен её применением в современных корпоративных решениях и соответствием требованиям к безопасности и масштабируемости, предъявляемым к модулю дипломной работы. [7]

3.1.2 Программный модуль разрабатывается с использованием языка программирования C# и фреймворка ASP.NET Core 8.0. Также применяются язык разметки HTML, язык таблиц стилей CSS и язык программирования TypeScript для клиентской части.

Язык C# является одним из наиболее популярных языков программирования для разработки корпоративных приложений благодаря своей типобезопасности, производительности и богатой экосистеме. ASP.NET Core 8.0 представляет собой современный кроссплатформенный фреймворк для создания веб-приложений и API, который обеспечивает высокую производительность, модульность и поддержку современных архитектурных паттернов.

Используемые технологии обеспечивают эффективную реализацию различных аспектов системы, включая обработку данных, взаимодействие с пользователем и визуализацию.

Преимущества:
- высокая производительность и масштабируемость;
- строгая типизация и безопасность;
- богатая экосистема библиотек и инструментов;
- поддержка современных архитектурных паттернов (чистая архитектура, микросервисы);
- кроссплатформенность;
- активное сообщество и поддержка Microsoft;
- встроенная поддержка асинхронного программирования.

Недостатки:
- более высокая кривая обучения по сравнению с некоторыми другими языками;
- требования к ресурсам выше, чем у некоторых альтернатив;
- необходимость настройки инфраструктуры для развертывания.

ASP.NET Core 8.0 – это современный асинхронный веб-фреймворк для разработки API и веб-приложений на языке C#. Он создан с упором на производительность, модульность и поддержку современных архитектурных подходов. ASP.NET Core позволяет разрабатывать высокопроизводительные приложения, используя асинхронные запросы и встроенную поддержку внедрения зависимостей. В настоящее время этот фреймворк широко используется в корпоративной разработке благодаря своей надежности, производительности и интеграции с облачными платформами.

ASP.NET Core основан на принципах чистой архитектуры, что позволяет явно разделять слои приложения и обеспечивать тестируемость кода. Фреймворк использует Entity Framework Core для работы с базами данных, обеспечивая удобный доступ к данным и поддержку миграций. Такой подход делает приложение более надежным и удобным в сопровождении.

Еще одной важной особенностью ASP.NET Core является поддержка асинхронного программирования на основе async/await, что позволяет обрабатывать запросы более эффективно и снижать нагрузку на сервер. В отличие от синхронных фреймворков, которые блокируют выполнение кода во время ожидания ответа от базы данных или внешнего сервиса, ASP.NET Core позволяет выполнять несколько операций одновременно, что значительно повышает производительность.

ASP.NET Core широко используется для разработки REST API, микросервисов и серверных частей веб-приложений. Он отлично подходит для построения высоконагруженных систем, так как позволяет легко интегрироваться с базами данных, очередями сообщений и другими внешними сервисами. Благодаря интеграции с OAuth2, JWT и другими механизмами безопасности, фреймворк также предоставляет удобные механизмы аутентификации и авторизации. [8]

3.1.3 Для клиентской части программного модуля используется библиотека React 19 с TypeScript. React – это декларативная JavaScript-библиотека для создания пользовательских интерфейсов, разработанная компанией Facebook. TypeScript добавляет статическую типизацию к JavaScript, что повышает надежность и сопровождаемость кода.

React нашел широкое применение в современных веб-приложениях благодаря своей производительности, компонентной архитектуре и богатой экосистеме. Библиотека позволяет создавать интерактивные пользовательские интерфейсы с эффективным обновлением DOM через виртуальный DOM.

Преимущества React с TypeScript:
- компонентная архитектура, способствующая повторному использованию кода;
- виртуальный DOM для эффективного обновления интерфейса;
- статическая типизация TypeScript для раннего обнаружения ошибок;
- богатая экосистема библиотек и инструментов;
- активное сообщество и постоянное развитие;
- поддержка серверного рендеринга (Next.js);
- удобные инструменты разработки (React DevTools).

Недостатки:
- кривая обучения для новичков;
- необходимость настройки сборки (Webpack, Vite);
- больший размер бандла по сравнению с некоторыми альтернативами.

Выбор React с TypeScript обусловлен требованием к созданию современного, отзывчивого и надежного пользовательского интерфейса для системы дистанционного банковского обслуживания. [9]

3.3 Разработка программного кода

3.3.1 Разработка программного кода регистрации пользователя

Используется метод RegisterAsync() класса UserService, представленный в Приложении А.

Изначально выполняется валидация входных данных методом RegisterRequest. Проверяется длина логина, пароля, email, телефона, ФИО и номера паспорта. Далее вызывается метод ExistsAsync() репозитория _userRepository для проверки уникальности логина.

При успешной валидации создается объект User. Пароль хешируется методом BCrypt.HashPassword(). После сохранения пользователя методом AddAsync() создается объект Session с токеном, генерируемым методом GenerateToken(). Метод возвращает объект AuthResponse с токеном сессии и данными пользователя.

3.3.2 Разработка программного кода выполнения перевода средств

Используется метод TransferAsync() класса OperationService, представленный в Приложении Б.

Изначально выполняется поиск счета получателя методами GetByIdAsync() или GetByAccountNumberAsync() с нормализацией номера методом NormalizeAccountNumber().

Далее проверяются права доступа методом UserMayAccessAccountAsync(), статус блокировки счетов, достаточность средств и совпадение валют. Для переводов юридическим лицам проверяется ИНН методом InnDigitsOnly().

Создается объект AccountOperation с типом "TRANSFER". Выполняется изменение балансов счетов. Операция фиксируется в журнале методом AddOperationAsync(). Метод возвращает объект OperationDto с данными операции.

3.3.3 Разработка программного кода подписания платежного поручения

Используется метод SignAsync() класса PaymentOrderService, представленный в Приложении В.

Изначально выполняется поиск платежного поручения методом GetByIdAsync(). Проверяется статус: подписать можно только документы со статусом "Draft".

Далее проверяется членство в организации методом UserIsMemberAsync() и права методом UserIsDirectorAsync() или MemberRoleAsync(). Вызывается метод EnsureDeviceAvailableAsync() для проверки устройства ЭЦП.

Формируется контрольная строка payload для подписи. Выполняется проверка подписи методом EnsureSignatureValidAsync(). При успешной проверке статус изменяется на "Signed". Для исполнения используется метод ExecuteAsync(), который списывает средства и создает запись в журнале.

В разделе «Переводы», изображенном на рисунке 3.7, пользователь выбирает счет списания, указывает номер счета получателя, сумму и назначение платежа. Система проверяет доступность счета, достаточность средств и совпадение валют. Для переводов юридическим лицам требуется указать ИНН получателя. После успешного перевода пользователь получает подтверждение с идентификатором операции.

[Рисунок 3.7 – Форма перевода средств]

3.4.4 Работа с банковскими картами

Раздел «Карты», показанный на рисунке 3.8, предназначен для управления картами. Отображается список карт с маскированным номером, сроком действия и статусом. Пользователь может выпустить новую карту, выбрав счет привязки и тип карты. Доступна функция блокировки карты.

[Рисунок 3.8 – Управление банковскими картами]

3.4.5 Работа со срочными вкладами

В разделе «Вклады», представленном на рисунке 3.9, отображаются открытые вклады с суммой, ставкой, сроком и статусом. Для открытия вклада пользователь выбирает счет-источник, указывает сумму и срок. Система рассчитывает ставку в зависимости от срока. Досрочное закрытие выполняется с пересчетом процентов.

[Рисунок 3.9 – Управление срочными вкладами]

3.4.6 Работа с организациями

Для корпоративных клиентов предназначен раздел «Организации», показанный на рисунке 3.10. Пользователь может зарегистрировать организацию, указав наименование, ИНН, КПП и адрес. При регистрации генерируется ключевая пара для электронной подписи.

[Рисунок 3.10 – Управление организациями]

Организация имеет участников с ролями «Директор» или «Бухгалтер». Директор управляет составом участников, бухгалтер создает и подписывает платежные поручения. Для организации открываются корпоративные счета.

3.4.7 Работа с платежными поручениями

Раздел «Платежные поручения», изображенный на рисунке 3.11, предназначен для корпоративных расчетов. Участник с ролью директора или бухгалтера создает поручение, указав реквизиты получателя и сумму. Созданное поручение имеет статус «Черновик».

[Рисунок 3.11 – Работа с платежными поручениями]

Для исполнения поручение подписывается электронной подписью. Система проверяет наличие ключа и формирует подпись. После подписания поручение переводится в статус «Подписан» и может быть исполнено со списанием средств.

3.4.8 Работа администратора

Для администраторов предусмотрен отдельный интерфейс с разделами: «Панель управления», «Пользователи», «Счета», «Организации».

В панели управления, показанной на рисунке 3.12, отображается статистика: количество пользователей, организаций, счетов и операций. В разделе «Пользователи» администратор может заблокировать или разблокировать пользователя, назначить административные права.

[Рисунок 3.12 – Панель управления администратора]

В разделе «Счета» администратор имеет доступ ко всем счетам, может изменить баланс, валюту, тип счета, заблокировать счет с указанием причины. В разделе «Организации» отображается список всех организаций с реквизитами и составом участников.

3.4.9 Управление профилем

В личном профиле, представленном на рисунке 3.13, пользователь может изменить контактные данные и сменить пароль. Для смены пароля требуется указать текущий и новый пароль. Доступно завершение активной сессии для защиты учетной записи.
